## b. Source SHAPE classification and the HARVEST route

### Shapes (`SKILL.md:38-63`; spec §5.1b.1 + nested-root check `migration-spec.md:512-534,553-581`; `codes.md:119-124`)

- **Shape A** — SUSHI/IG-Publisher project: `sushi-config.yaml` **or** `ig.ini` at root plus `input/fsh/`. FSH exists; step 4 transfers it. `input/fsh/` present-but-empty → configuration error, not a no-op.
- **Shape A (nested)** — the scaffolding check runs to **depth 3** (skipping `.git`, `node_modules`, `output`, `temp`, `input-cache`); a hit below root (measured: `kerndatensatzmodul-strukturdaten` nests everything under `Resources/`) re-roots the migration, recorded as a `decision` line `shape=A (nested at <path>)`. goFSH-ing such a repo would discard the author's FSH "with the ratio green".
- **Shape B** — raw FHIR resource repository, no scaffolding: "the normal state of a module authored in Forge and published on Simplifier … the most authentic case this skill exists for" (`SKILL.md:45-59`). **Detected by content, not folder name**: a file is a FHIR resource if it parses and carries a `resourceType` (JSON) / root element under `http://hl7.org/fhir` (XML) — folder names are hand-chosen and often German (`migration-spec.md:553-557`). Classification has a third bucket: **narrative-bearing text files**, each inventoried with a disposition (the reference module ships a 43-line German README + a 126-line CodeSystem markdown mirror — `migration-spec.md:566-576`). Route: step 2b derives FSH via goFSH; from step 3 the paths are identical.
- **Neither** — no scaffolding and no FHIR resources: not an IG project. "Say so and stop. Do not scaffold one." (`SKILL.md:60-63`)

Target-state classification is separate (pre.3, `SKILL.md:65-70`): re-migration / plain Simplifier / hybrid.

### The HARVEST route (step 2c; spec §5.1c discovery + §5.1d harvest)

Applies "shape B always, and any shape A whose pages live on the platform" (`SKILL.md:237`). Order of sources, most trustworthy first — "nothing is not the third one":

1. **① Authenticated project download** (`<project-slug>/$actions/downloading`) — the author's markdown; login-gated (measured: anonymous → `/login?ReturnUrl=…`; four probed anonymous alternatives 404/HTML — "no verified anonymous project download exists"). A human downloads in their own browser and names a path outside the repo; the agent logs `narrative-source=project-download`. "Never invent a credential mechanism, ask for a password or store a token — the gate is the point." Nobody available → `project-download-unavailable:` and fall through (`SKILL.md:240`, `migration-spec.md:1328-1355`).
2. **② The guide harvest** — `guide-harvest.sh --guide-url "https://simplifier.net/guide/<key>/<Root>?version=<v>" --out … --keep-html …` (`SKILL.md:241-250`). Anonymous, verified, and **a rendering** (directives already expanded; a rendered artefact view is not the resource it renders). It discovers the page tree from the root's own `href`s (slugs read, never constructed — "Anwendungsfälle / Informationsmodell" → `AnwendungsflleInformationsmodell`), pins every page to `?version=`, isolates `<div id="preview-content">` by depth-scanning, converts to Markdown with a provenance header + `TODO:REVIEW`, classifies each page `narrative` / `artefact-view`. `--out` has **no default** — it is step 5's input, not the template's page set.
3. **③ Nothing** — never an outcome; an unreachable source is escalated to Gate B and named. Skipping the harvest "ships the template's starter pages under the module's name" — which is exactly what happened to the earlier Consent migration (`SKILL.md:54-58`, `provenance.md:56`).

## c. The page-map contract

**Generate — validate — bind** (spec §9f, `migration-spec.md:2254-2277`): `migration-log/page-map.tsv` is "the binding intermediate of the whole narrative migration". Step 3 (the `5.4c page-routing` run) GENERATES and VALIDATES it, a human reviews/edits **the file itself**, step 5 CONSUMES ONLY it, step 7b (C3/C6) CHECKS against it. "No routing decision lives anywhere else."

- **Generator:** `scripts/page-structure-advice.py` (2,606 lines; SCRIPT_VERSION 1.3.0) — "IT PROPOSES AND NEVER EDITS A MODULE"; writes at most the `--out` report and the `--map` TSV, refuses to write anywhere but the target's `migration-log/` (`page-structure-advice.py:20-28`). Invocation (`SKILL.md:454`): `page-structure-advice.py --source <src> --target . --out migration-log/page-structure-advice.md --map migration-log/page-map.tsv`.
- **Routing rule** (spec §9e, `migration-spec.md:2185-2205`; first match wins): (1) one-artefact content → `input/intro-notes/<Type>-<id>-intro.md` + German mirror, no page/menu/`pages:`/`.po` entry; (2) family overview → section on an existing index page; (3) an agreed page owns it → merge (size gate applies); (4) cross-cutting → its own page, with 4a presentation (≥3 children → **hub**, ≤250 words) and 4b visibility (menu entry only if total ≤33, dropdown ≤10, top level ≤8, depth ≤2 — surveyed across real IGs, and every surveyed IG caps depth at 2; else `pages:`-nested); (5) size gate: >2500 words, >4 merged sources or ANY repeated heading → re-route/split.
